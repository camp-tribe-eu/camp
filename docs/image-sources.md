# Image sources and rights (CAMP-469)

The card says: no image without a record of its source and rights. This
file is that record for the eight decorative images in
`apps/web/public/banners/`. There is no public page of image credits yet;
until there is one, this file is the only place the record lives.

## 🔴 These are AI-generated and are NOT photographs of any place

The eight banners are **generated by an AI model**. They look like
photographs. They are **not photographs of any real campsite, country,
road or place**, and nobody stood where they show. The site prints "No
stock photography and no AI-generated images of places nobody has
visited". With an illustration the difference was obvious to a reader; with
photorealism it is not, so it is stated here and must be kept true:

- never caption, alt-text or describe them as a real location, a real
  campsite or "our" campsite;
- never place one where the page promises a photograph of a specific
  place (a campsite page, a region hero meant as that region);
- they are decoration for generic slots: page banners and two cards.
- every prompt forbids a recognisable country, mountain, city, landmark,
  sign, number plate, flag, text, logo and people, and each output was
  looked at before commit for those and for objects floating without a
  shadow.

The reader-facing statement lives in `apps/web/src/app/llms.txt/route.ts`
("The decorative banners are not photographs"). `scripts/images/check-banners.mjs`
runs in CI and fails if a raster file sits in `public/banners/` while that
sentence is missing. The service and model are named for readers on the
attribution page, section "Decorative images" (migration
`1796600000000-AttributionBannerImages`, version 1.4). The campsite page block "We don't publish pictures we
haven't verified" was measured and left alone: it says "here", the page
renders no banner, and a banner shows no place, so it stays true.

## 🔴 Ordering: do not ship attribution 1.4 before the components use `.webp`

🔴 Migration `1796600000000-AttributionBannerImages` (attribution 1.4) must NOT be rolled out before the components reference the `.webp` files. As of 12.11.2026 they do (CAMP-469 PR): `apps/web/src` references `.webp` and no longer `.svg` for banners. Ship them together, never the migration alone.
